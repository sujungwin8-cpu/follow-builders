# follow-builders 수집기 사용 안내

이 포크의 피드 생성기 안내입니다. 원본 에이전트 스킬의 설치·알림 설명과 구분합니다.

## 키 없이 시작하기
저장소 루트에서 `node scripts/generate-feed.js`를 실행하면 공개 블로그를 수집합니다. X·팟캐스트 키가 없으면 두 공급원은 건너뜁니다. 블로그만 의도적으로 실행하려면 `node scripts/generate-feed.js --blogs-only`를 사용합니다. 이 명령은 키가 있어도 유료 API를 호출하지 않습니다.

기존 예약은 매일 06:17 UTC(한국 15:17)입니다. Actions 예약은 정시 보장이 없으며 실제 실행 시각은 지연될 수 있습니다. 수집 코드·설정 변경이 main에 반영될 때도 실행합니다. 수집 파일 커밋 자체는 다시 수집을 촉발하지 않습니다.

## 인증이 필요한 수집 추가
저장소 Settings → Secrets and variables → Actions에서 필요한 Repository secret을 등록합니다.

- X: `X_BEARER_TOKEN`. X API v2의 `GET /2/users/by`와 `GET /2/users/:id/tweets`를 사용할 수 있어야 합니다. 해당 계정의 서비스 권한·잔액·호출 한도는 따로 확인해야 합니다.
- 팟캐스트: `POD2TXT_API_KEY`. 현재 코드가 사용하는 pod2txt의 전사 API 인증과 사용 가능량이 필요합니다. 공개 RSS 목록을 읽을 수 있다는 사실만으로 전사문 수집이 복구된 것은 아닙니다.

키를 등록한 뒤 Actions → Generate Feeds → Run workflow에서 각각 `tweets-only`, `podcasts-only`로 검증합니다. 키 없는 단독 요청은 오류로 종료합니다. 기본 `all`은 키가 등록된 공급원을 자동으로 포함하므로 키 등록 이후에는 그 서비스 사용량이 발생할 수 있습니다. 이 수리에서 키 발급·구매·결제는 수행하지 않았습니다.

## 결과 읽기
`feed-status.json`의 실행별 상태와 Actions의 Feed collection 요약을 먼저 확인합니다.

- `success`: 요청한 수집을 완료했습니다. 새 글 0건도 정상일 수 있습니다.
- `partial`: 일부 콘텐츠는 저장했지만 개별 요청 오류가 있습니다. 오류를 확인해야 합니다.
- `failed`: 해당 피드를 갱신하지 못했습니다. 기존 파일·날짜를 보존합니다. 다른 피드의 성공 결과는 저장한 뒤 워크플로를 실패로 표시합니다.
- `skipped`: 키가 없거나 단독 모드에서 선택하지 않은 공급원입니다. 기존 피드가 있어도 이번 수집 성공으로 해석하지 않습니다.

`feedUpdated`와 `feedGeneratedAt`을 함께 봅니다. 파일이 존재한다는 것만으로 최신 수집이라고 판단하지 마세요. 키가 없는 공급원을 건너뛰고 블로그만 성공한 실행은 정상 종료하지만 X·팟캐스트 복구를 뜻하지 않습니다. 모든 수집 요청이 실패한 경우에는 성공으로 표시하지 않습니다.

블로그 본문에 게시일이 있으면 최근 72시간을 벗어나는 글은 제외합니다. 날짜를 찾지 못한 글은 `publishedAt: null`을 유지하므로 정확한 작성 시각이 검증된 글로 간주할 수 없습니다. 외부 사이트의 HTML 변경에는 추후 파서 수정이 필요할 수 있습니다.

## 시험 및 문제 확인
`cd scripts && npm test`로 외부 접속이나 유료 API 없이 회귀 시험을 실행합니다. 모의 인증 성공은 실제 서비스 인증 성공을 보장하지 않습니다.

실제 복구 확인에는 Actions의 수집 단계 성공, 후속 피드 커밋, `feed-status.json`의 공급원별 상태를 확인합니다. 이전 실패 실행을 단순 재실행하면 예전 코드가 사용될 수 있으므로 변경 후 main에서 새 Run workflow를 실행합니다.

## 요약과 전달의 범위
Generate Feeds는 이 저장소에 원자료 JSON을 저장합니다. Reddit 수집이나 ChatGPT 브리핑 전송은 구현돼 있지 않습니다. `prepare-digest.js`의 기본 데이터 출처는 원본 `zarazhangrui/follow-builders`입니다. 이 포크 피드를 요약·전달에 사용하려면 별도 소비 경로를 명시적으로 설정하는 작업이 필요합니다.
